# CAMS documentation screenshots

`docshots` renders the production `UI` QML module directly into lossless PNG files. It is intended for stable illustrations in the Typst book and does not capture the desktop, cursor, console, or operating-system window decorations.

## Run

From the repository root:

```bash
uv run python scripts/docshots.py welcome
uv run python scripts/docshots.py workspace
uv run python scripts/docshots.py devices
uv run python scripts/docshots.py vlan
uv run python scripts/docshots.py all
```

The defaults are a 1600 x 1000 logical QML layout, scale 2, and the light theme. The resulting PNG is 3200 x 2000 pixels. Qt Quick renders that target resolution directly with `QQuickItem.grabToImage()`; the tool does not resize a captured raster with Pillow.

Options:

```text
--width INT          logical width (default: 1600)
--height INT         logical height (default: 1000)
--scale FLOAT        Qt render multiplier (default: 2)
--theme light|dark   fixed theme (default: light)
--output-dir PATH    destination directory
```

The default destination is resolved from the repository location, not the current working directory:

```text
<repo-root>/documentation_assets/ui/docshot/
├── core/             welcome.png + chapter-03 workflow
├── project/          workspace.png
├── devices/          devices.png + chapter-04 workflow
├── switching/vlan/   VLAN workflow
└── core/dialogs/     dialog regression workflow
```

Existing files are replaced atomically and filenames never contain timestamps.

## Current shots

- `welcome`: the real `UI/Welcome` window with deterministic, documentation-only recent projects.
- `workspace`: the real `UI/Main` window with a clean campus-lab fixture.
- `devices`: the same workspace with `R1` selected and its real device view loaded.

## VLAN workflow

Run the complete VLAN documentation sequence from the repository root:

```bash
uv run python scripts/docshots.py vlan
```

The workflow renders the production `Main`, `SwitchWorkspace`, `VlanPage`, and
View & Push preview QML into:

```text
<repo-root>/documentation_assets/ui/docshot/switching/vlan/
```

It opens the documentation fixture `SW1` at `192.0.2.11` (Cisco IOS, role
`sw2`), navigates through **Switching → VLAN**, and uses the real Add, field,
State selector, Save, inventory-selection, and preview UI. The initial fixture
contains VLAN 1 `default`, VLAN 10 `Management`, and VLAN 20 `Users`; the flow
creates VLAN 30 `Guest` in state `active`. Existing VLANs are marked as already
synchronized, so the preview is generated by the application for VLAN 30 only.

Every run creates new temporary databases and settings. The documentation
terminal disables network I/O, and the workflow opens only the preview. It never
selects Push and never sends configuration to a device.

The inventory uses only RFC 5737 documentation addresses (`192.0.2.0/24`), the fixture username `admin`, and a temporary non-secret password. It never opens SSH/Telnet sessions, starts Syslog, captures an interface, transfers files, or launches the external terminal. Both SQLite databases, settings, backups, and SFTP local storage live under a temporary directory and are removed after each shot.

## Add a shot

1. Add a `ShotSpec` to `docshots/shots.py`. Point it at an exported type in `UI/qmldir`.
2. Add only the deterministic setup state needed by that shot in `docshots/runtime.py`. Keep device and workspace data in `FixtureBundle`; never read a developer project or the production `data` databases.
3. For a full window, use `capture_window()`. For a named panel or other `QQuickItem`, locate it by `objectName` and use `capture_item(item, QSize(...))`.
4. Extend `tests/test_docshots.py` and run the structure, compile, and unit-test commands below.

New fixture addresses must come from `192.0.2.0/24`, `198.51.100.0/24`, or `203.0.113.0/24`. Do not put real hostnames, paths, usernames, passwords, tokens, or keys in fixtures.

## Readiness and limitations

The renderer waits for QML loading, asynchronous incubation, fixed logical geometry, and two identical Qt-rendered frames with a bounded timeout before taking the final image. A null image, unstable scene, bad PNG encode, or unexpected pixel size exits non-zero with a diagnostic.

Qt Quick framebuffer capture cannot include native Open/Save/Folder dialogs or external terminal processes. Those windows are intentionally out of scope; no OS screenshot dependency is added. The environment must provide a functional PyQt6 offscreen/software Qt Quick backend and the fonts used by the application.

`add-device` is not a separate registered CLI token; use the existing `chapter-04` workflow for its fixture-driven device forms/actions. Native OS dialogs remain outside Qt framebuffer capture.

Verification commands:

```bash
uv run python scripts/validate_structure.py
uv run python -m compileall .
uv run python -m unittest discover -s tests -v
```

## Destination transition and overrides

Chapter workflows are registered:

```sh
uv run python scripts/docshots.py chapter-03
uv run python scripts/docshots.py chapter-04
uv run python scripts/docshots.py dialogs
uv run python scripts/docshots.py chapter-03 --output-dir /tmp/cams-chapter03-check
```

`--output-dir` is an **exact destination**, for every shot/workflow, including VLAN and chapters. Default `all` dispatches welcome/workspace/devices to their individual domains; an override keeps all three directly in that chosen directory. Defaults are checkout-relative, independent of CWD, and reject symlink escape; explicit one-off output may be outside the checkout. No command is forced back into canonical storage when an override is given.

This infrastructure change does not move/regenerate any existing screenshot. Renderer filenames/order stay unchanged until the later semantic output-map/asset batch; chapter numbers remain CLI workflow names, not proposed long-term asset taxonomy. Temporary test captures are isolated, never written over repository images. `00_book/assets/` is solely generated staging via `scripts/sync_documentation_assets.py`, never a docshot default. Terminal images and the terminal renderer are frozen external assets, outside docshot destination migration.

Run destination contracts without application runtime imports:

```sh
python -m unittest tests.test_docshot_destinations -v
```

Full Qt/workflow repeatability tests require the project environment (`uv run ...`). The chapter-03 offline training-package test additionally requires `00_book/fixtures/chapter-03/build_fixture.py`. That builder is absent in the current checkout; this existing test prerequisite is reported rather than invented by the asset infrastructure phase.
